## Falhas de processo que não podem se repetir

1. Considerar uma alteração Android pronta só porque o bundle web ou o Gradle compilou.
2. Pedir que o usuário repita um teste sem antes consultar logs, hipótese e evidência da tentativa anterior.
3. Corrigir um total financeiro sem localizar quais lançamentos, parcelas ou recorrências causaram a divergência.
4. Aplicar dados importados diretamente na base principal sem backup e comparação normalizada.
5. Remover dependências `@lovable` apenas porque o Supabase foi migrado. O MCP e integrações ainda dependem delas.
6. Marcar uma etapa de redesign como concluída sem validar os estados e o dispositivo definidos no roadmap.
7. Considerar uma função dependente de agendamento (cron) como "funcional" só porque uma invocação manual respondeu com sucesso. Sempre conferir se existe um job realmente agendado (`cron.job` ou equivalente) rodando sozinho, sem intervenção.
